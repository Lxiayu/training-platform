# 启航编程管理系统 · 三端功能需求（学员 / 家长 / 教师）

> 本文档回答一个问题：在 v0.4「四类身份登录 + 服务端门禁」之后，**教师端、学员端、家长端到底还缺哪些功能、为什么缺、先补什么**。
> 文档只做需求挖掘与方案设计，不含实现；数据模型增量与《01-数据库设计》第 11 章演进方向保持一致。

## 0. 结论摘要

1. **现状**：三端目前只有一张「只读工作台」——能看学籍、班级、已缴金额，**不能办任何事**；后台 12 个模块全部面向员工。
2. 用户点名的 7 件事（作业提交、课表查看、缴费详情、课程查看、学生请假、教师审批、授课查看）不是 7 个孤立页面，而是 **4 条业务闭环**：教学活动（课次）、作业、请假、费用。
3. **最大前置卡点**：`classes.schedule` 是自由文本（如「周六 09:00-10:30」），既生成不了课表，也无法把作业 / 请假 / 考勤挂到「某一节课」。**必须先结构化排课**，否则其余功能全部悬空。
4. **缴费详情缺「应收」概念**：现有 `payments` 只是收款流水，家长看不到「应缴 / 已缴 / 欠费」。需补 `bills` 账单表；上线前可用「课程价」生成一条应缴做过渡。
5. 建议新增 **9 张核心表（另加 1 张请假-课次关联表）、约 40 个接口**，按 P0 / P1 / P2 三期落地；**P0 约 18–22 人日**（1 人 4 周 / 2 人 2 周），即可交付「课表 + 作业 + 请假 + 家长缴费详情 + 站内通知」的最小闭环。
6. 三端统一原则：**数据范围即权限**——教师只看自己带的班、家长只看关联的孩子、学员只看自己；服务端强制校验，前端隐藏只作体验优化。

## 1. 现状盘点

### 1.1 已有能力（v0.4）

| 端 | 入口 | 能看到 | 能操作 | 服务端门禁 |
| --- | --- | --- | --- | --- |
| 学员 | `portal.html` | 我的学籍（班级 / 课程 / 教师 / 上课时间）、已缴费用、缴费笔数、学籍状态 | 无（仅改个人资料 / 密码） | `/portal/student/profile`（`require_student`） |
| 家长 | `portal.html` | 关联学员列表（姓名 / 年级 / 班级 / 课程 / 教师 / 状态） | 无 | `/portal/parent/children`（`require_parent`） |
| 教师 | `portal.html` | 所带班级、在读学员数、班级课表文本 | 无 | `/portal/teacher/classes`（`require_teacher`） |
| 员工 | `dashboard.html` 等 10 页 | 全部业务数据 | 全部 CRUD（按角色） | `require_admin` / `require_roles` |

### 1.2 五个结构性缺口

| # | 缺口 | 直接导致做不了的需求 | 根因 |
| --- | --- | --- | --- |
| 1 | **课表不可计算** | 学员课表、家长课表、教师授课查看、上课提醒、按课次请假 | `classes.schedule` 为自由文本，没有「日期实例」；《01》§11.2 已列为演进项 |
| 2 | **作业无载体** | 作业提交、批改、提交率统计、催交 | 无 `homeworks` 实体；`resources` 只是课件库，不是作业 |
| 3 | **请假无流程** | 学生请假、家长代请假、教师审批、销假 | 无 `leave_requests`，无审批状态机，无与考勤的联动 |
| 4 | **考勤不存在** | 到课记录、出勤率、缺勤告警 | 无 `attendance`；请假通过后也无处落「这节课不算缺勤」 |
| 5 | **缴费无账单** | 家长缴费详情、欠费提醒、续费 | `payments` 只有「收到的钱」，没有「应收多少」；也没有 `billId` 把流水挂到账单上 |
| 6 | **无消息触达** | 作业提醒、审批结果、缴费提醒、上课提醒 | 三端只能靠用户主动登录查看 |

### 1.3 一句话结论

> **先把「课次」造出来，作业、请假、考勤、课表才有挂载点；再把「账单」造出来，家长的缴费详情才说得清。**

## 4. 详细需求

### 4.1 学员端

#### F-S-01 我的课表 ★

- **入口**：门户首页第一屏「今日课程」卡片 + 「我的课表」页签。
- **展示**：周视图（默认）/ 月视图 / 列表视图；周视图横轴周一至周日，纵轴时间段。
- **课次卡字段**：日期、起止时间、班级、课程、教师、教室、课次主题、状态（待上课 / 已上课 / 已取消 / 已调课 / 已请假）。
- **规则**：
  1. 仅展示本人当前班级的课次（服务端按 `studentId → classId` 过滤）；
  2. 已取消课次保留在原时间位并置灰，附取消原因；
  3. 调课显示「原时间 → 新时间」双行，不允许静默改时间；
  4. 已通过请假的课次打「已请假」标记，不再提示缺勤；
  5. 时区固定 `+08:00`，跨天课程按开始日期归档。
- **异常**：班级未排课 → 空状态「老师还未排课，请稍后查看」；课次全部取消 → 提示联系班主任。
- **验收**：学员 XS001 只能看到 BJ002 的课次；取消的课次不出现在「今日课程」但保留在周视图；同一课次不会重复出现。

#### F-S-02 作业列表与详情 ★

- **页签**：待提交（默认，带角标数）/ 已提交 / 已批改 / 全部。
- **列表字段**：标题、课程、关联课次、截止时间、剩余时间（>24h 常规色 / ≤24h 警示色 / 已逾期红色）、状态、得分。
- **详情**：教师要求（文本 + 附件）、我的提交、批改结果（分数 / 评语 / 批改时间）、历史提交次数。
- **规则**：已批改不可再改；逾期后仍可查看；被「退回重做」的作业回到待提交并高亮原因。
- **验收**：待提交角标 = 未提交且未截止（或允许迟交）的数量；批改后列表即时更新。

#### F-S-03 作业提交 ★

- **表单**：文本作答（富文本不做，纯文本 + 换行）+ 附件（最多 3 个，单个 ≤ 20MB，类型白名单：pdf / docx / pptx / zip / png / jpg / py / txt）+ 「存草稿」。
- **规则**：
  1. 截止前可反复提交，**保留最后一次**并记录提交次数；
  2. 截止前可撤回（仅未批改）；截止后不可撤回；
  3. 截止后是否可交由作业级 `allowLate` 决定，迟交打「迟交」标记，教师可见迟交时间；
  4. 提交成功即扣减待办角标，并发一条「已提交」确认（站内信即可）；
  5. 附件必须走鉴权下载，不允许把 `uploads/` 目录直接暴露为静态资源。
- **状态机**：`未提交 → 已提交 → 已批改`；`已提交 → 退回重做 → 已提交`。
- **异常**：附件超限 / 类型不符 → 前端即时拦截并提示；重复点击提交 → 幂等（同一作业只保留一条提交记录 + 版本号）。

#### F-S-04 请假申请 ★

- **表单**：请假类型（病假 / 事假 / 其他）、请假范围（**按课次多选**，推荐；不支持则退化为日期区间）、事由（≥ 5 字）、附件（病历等，可选）。
- **展示**：待审批 / 已通过 / 已驳回 / 已撤销 四态列表；含审批人、审批意见、审批时间。
- **规则**：
  1. 只能对「未来未开始」的课次申请；已上课次不允许补请（由教师考勤补录修正）；
  2. 同一课次不可重复申请（学员、家长任一方已申请即拦截，返回 409）；
  3. 待审批可自行撤销；已通过不可撤销，需联系教师改考勤；
  4. 审批通过后，对应课次考勤自动写为「请假」，不计缺勤；
  5. 请假最小单位是**课次**，不是「天」——避免半天课与整天假的歧义。
- **验收**：跨班课次不能选；审批通过后学员课表出现「已请假」；重复提交返回 409 且提示「该课次已有请假申请」。

#### F-S-05 我的考勤 ☆

- 汇总：出勤率、出勤 / 迟到 / 早退 / 请假 / 缺勤次数。
- 明细：按课次列表（日期、课程、状态、备注）。
- 规则：只统计「已点名」课次；教师未点名不显示为缺勤。

#### F-S-06 我的缴费 ★

- 顶部汇总：应缴 / 已缴 / 待确认 / 欠费（无账单时仅显示已缴与流水）。
- 明细：账单列表（账期、课程、金额、状态、到期日）+ 流水列表（日期、金额、方式、状态）+ 收据下载（P1）。
- 规则：金额统一 2 位小数；「待确认」不计入已缴；「已作废」「已退款」灰色展示。
- 口径：与后台缴费管理逐笔一致，汇总差额必须为 0。

#### F-S-07 我的课程与课件 ★

- 课程卡：课程名、难度、总课时、已上课时、剩余课时、带班教师、班级、进度条。
- 课件：只显示「本人班级对应课程」的已发布资源，可下载计数；**不得出现其他班级 / 其他课程的课件**。
- 规则：资源可见范围 = `resources.courseId == 学员班级.courseId`（无需改表）。

#### F-S-08 学习报告 ☆

- 作业得分趋势（最近 10 次）、出勤率、教师评语、阶段报告（P1）。
- 只读；不展示其他学员的对比排名（隐私）。

#### F-S-09 消息中心 ★

- 类型：作业发布 / 截止提醒 / 请假结果 / 缴费提醒 / 上课提醒 / 机构公告。
- 未读数角标；点开即已读；支持「全部已读」。
- P0 仅站内信；P1 接微信模板消息（见 §9.3）。

#### F-S-10 个人资料 ★

- 复用现有 `PUT /auth/profile`、`PUT /auth/password`；补充「绑定 / 更换手机号」为 P1（需验证码）。

### 4.2 家长端

#### F-P-01 多孩子切换 ★

- 顶部孩子切换器（头像 + 姓名 + 班级），记住上次选择；单孩子时隐藏切换器。
- 规则：只能切换到 `student_parents` 中与本人关联的孩子；越权返回 403。
- 现状：关联表已支持一对多，缺的只是前端与「按孩子维度取数」的接口参数。

#### F-P-02 孩子课表 ★

- 与 F-S-01 同构，只读；额外展示带班教师与教室；调课 / 停课变化必须有角标提示。
- 默认展示「本周」，可切换孩子。

#### F-P-03 作业完成情况 ★

- 列表：作业标题、课程、截止时间、状态（未提交 / 已提交 / 已批改 / 逾期）、得分、教师评语。
- 规则：家长**不能代交作业**（保持作业真实性）；逾期红色标注；P1 增加「提醒孩子」站内信。
- 价值判断：家长最高频的诉求不是看题，而是「交没交、批没批」。

#### F-P-04 请假（代申请）★

- 与 F-S-04 同一套表单，`applicantType = parent`，记录操作人。
- 规则：只能给关联孩子请假；可查看审批进度；审批结果同时通知家长与学员。
- 去重：孩子本人已申请同一课次时，家长端提示「已提交，等待审批」。
- 边界：家长撤销仅限「待审批」；已通过需教师改考勤。

#### F-P-05 考勤与到课提醒 ★/☆

- 查看：按课次的到课记录（出勤 / 迟到 / 早退 / 请假 / 缺勤）。
- 提醒（P1）：教师点名提交后 30 分钟内推送「已到课 / 缺勤」；**缺勤需教师在 2 小时内确认**再推送，避免误点造成家长恐慌。
- 规则：请假已通过的课次显示「请假」，不推缺勤。

#### F-P-06 缴费详情 ★（本次重点）

**页面结构**

1. 顶部孩子切换 + 汇总卡：应缴 / 已缴 / 待确认 / 欠费；
2. 账单一览：账期、课程、班级、应缴金额、已缴金额、状态（待缴 / 部分缴 / 已缴 / 已逾期 / 已作废）、到期日、操作（去缴费 / 查看收据）；
3. 流水明细：日期、金额、方式（微信 / 支付宝 / 现金 / 转账）、状态（待确认 / 已支付 / 已退款 / 已作废）、经办人、备注；
4. 收据 / 发票：P1 收据下载，P2 发票申请。

**口径（必须与财务一致）**

- 应缴 = Σ 有效账单 `amount`（不含已作废）；
- 已缴 = Σ 流水 `status = 已支付` 的 `amount`（不含待确认、已退款、已作废）；
- 欠费 = 应缴 − 已缴（≥ 0）；
- 部分缴：`0 < 已缴 < 应缴`；逾期：到期日已过且未缴清（查询时计算，不落库）。

**过渡方案（`bills` 未上线时）**

- 以「班级对应课程价」生成一条虚拟应缴，标注「按课程价估算，以机构账单为准」；
- 历史流水无 `billId` 时归入「历史流水」，不参与欠费计算，避免凭空造出欠费。

**验收**：随机抽 3 名学员，家长端汇总与后台 `/payments/stats` 逐笔核对一致；待确认流水不计入已缴；作废后欠费金额回滚。

#### F-P-07 课程查看 ★

- 课程介绍（简介、难度、总课时、适合人群）、班级信息（教师、教室、上课规律）、进度（已上 / 总课时）、剩余课时、续费入口（P2 引导到线下或在线支付）。

#### F-P-08 教师评语 / 阶段报告 ☆

- 按课次或按月的教师评语、课堂表现、阶段学习报告；只读。
- P2 支持导出 PDF（家长会 / 续费材料）。

#### F-P-09 通知与公告 ★

- 与 F-S-09 共用消息中心，按孩子维度聚合；机构公告全员可见。

#### F-P-10 发票 / 退费申请 ○

- 家长提交申请（金额、抬头、原因）→ 后台财务处理 → 结果通知。
- 规则：**申请不等于退款**；退款必须走后台 `refunds` 单据（《01》§11.8），家长端不直接改 `payments`。

### 4.3 教师端

#### F-T-01 我的授课（授课查看）★

- **今日卡片**：下一节课倒计时、班级、教室、应到人数、已请假人数、作业待批数。
- **周课表**：与自己相关的课次（含代课），点击进入课次详情。
- **课次详情**（「授课查看」的真正落点）：
  1. 基本信息：班级、课程、日期时间、教室、课次主题；
  2. 学员名单：姓名、学号、学籍状态、请假状态、上次作业提交情况；
  3. 快捷动作：点名、布置作业、查看作业、发起调课。
- **规则**：只显示 `teacherId = 本人` 或代课教师的课次；跨班访问 403；已结课班级只读。
- **验收**：教师 JS001 只能看到 BJ002 / BJ003 的课次；课次详情中的学员名单与班级在读学员一致。

#### F-T-02 点名 / 考勤 ★

- 默认全部「出勤」，教师只需点异常（迟到 / 早退 / 请假 / 缺勤 + 备注），一键提交。
- 已通过请假的学员自动预填「请假」且不可改（如需改，先改请假单）。
- 补录：课次结束后 7 天内可补录，需填备注；超过 7 天需教务操作（P1）。
- 提交后锁定；修改留痕（谁改、何时、原值 → 新值，P1）。
- **验收**：点名提交后家长端 1 分钟内可见状态；同一课次重复点名幂等；请假学员不会被记缺勤。

#### F-T-03 作业布置 ★

- 字段：标题、说明（纯文本 + 换行）、附件、关联课次（默认本节）、截止时间、是否允许迟交、满分（默认 100）。
- 对象：默认全班；P1 支持勾选个别学员（补交 / 分层作业）。
- 发布即通知（学员 + 家长）；截止前可编辑；**已有提交时不可删除**，只能「截止 / 归档」。
- 规则：截止时间必须晚于发布时间；作业必须属于自己带的班级。

#### F-T-04 作业批改与统计 ★

- 列表：已交 / 未交 / 已批改 三个页签；未交名单一键催交（P1）。
- 批改：分数（0–100）+ 评语 + 「退回重做」；支持键盘连续批改（下一条）。
- 统计：提交率、平均分、分数段分布、迟交人数、未交名单导出（CSV，P1）。
- 规则：只能批改自己布置的作业；退回后学员可重交，原成绩作废并留痕。

#### F-T-05 请假审批 ★

- 待办列表（侧边栏角标）；默认按「上课时间」升序，急的在前。
- 操作：通过 / 驳回（**驳回必填理由**，≤ 100 字）；P1 支持批量通过。
- 审批后：自动写对应课次考勤 = 请假；通知学员 + 家长；记录审批人与时间。
- 规则：只能审批自己班级的请假；跨班或代课冲突转教务（P1 转交功能）；已审批不可重复操作（409）。
- **验收**：审批通过后考勤、课表、通知三处状态一致；驳回后学员可重新申请。

#### F-T-06 调课 / 停课 / 补课申请 ☆

- 教师发起 → 教务审批 → 生效后改课次状态并通知全班。
- 字段：原课次、新时间 / 新教室、原因、是否补课。
- 规则：冲突检测（同教师 / 同教室时间重叠）在服务端做，前端只提示。

#### F-T-07 成绩与评语 ☆

- 按学员录入课次评语 / 月度评语（课堂表现、进步点、待改进）；作业成绩自动汇总，不重复录入。
- 阶段报告（P2）：按学员生成，家长端只读。

#### F-T-08 课件上传与关联 ☆

- 上传到「本人授课课程」，可关联课次；可见范围 = 该课程的在读班级。
- 复用现有 `/resources` 写接口（后台已限员工，需为教师开放「本人课程」范围，注意不要放开全量删除权）。

#### F-T-09 课时统计 ☆

- 本月已授课时、待授课时、学员平均出勤率、作业平均提交率、待批作业数。
- P1 月度课时报表 CSV（用于课时费核算）。

#### F-T-10 消息与公告 ★

- 与 F-S-09 共用；额外接收「待审批」「待批改」「调课结果」提醒。

## 5. 关键流程设计

### 5.1 作业闭环

```
教师布置（草稿→已发布）
   │  通知：学员 + 家长
   ▼
学员提交（未提交→已提交；迟交打标）
   │
   ├─ 教师批改 → 已批改（分数 + 评语）→ 通知学员/家长
   └─ 教师退回 → 退回重做 → 学员重交 → 已提交（原成绩作废）
   │
截至到期 → 已截止（未交者进入「未交名单」）→ 可催交 → 归档
```

| 规则 | 说明 |
| --- | --- |
| 幂等 | 同一学员 × 同一作业只有一条有效提交记录，重复提交更新内容并累加版本 |
| 迟交 | `now > dueAt` 且 `allowLate` 才允许，`lateFlag = true`，界面标「迟交」 |
| 退回 | 必须填理由；退回后状态回「待提交」，原分数置空但留历史 |
| 删除保护 | 已有提交的作业不可删除（409），只能归档 |
| 通知 | 发布、截止前 24h、批改、退回四个触点 |

### 5.2 请假闭环（与考勤联动）

```
学员/家长提交（待审批）
   │ 通知：任课教师
   ▼
教师审批 ──通过──▶ 已通过 ──▶ 自动写考勤=请假 ──▶ 通知学员+家长
   │                    │
   └──驳回（必填理由）──▶ 已驳回 ──▶ 通知（可重新申请）
                        │
待审批/已通过 ──撤销（仅待审批可自助）──▶ 已撤销
```

| 规则 | 说明 |
| --- | --- |
| 唯一性 | `(studentId, sessionId)` 唯一，重复申请 409 |
| 时间窗 | 仅未来课次可申请；开课后只能由教师考勤补录 |
| 审批权限 | 该课次 `teacherId` 或班级班主任；教务可代批（P1） |
| 考勤联动 | 审批通过 → `attendance.status = 请假`；撤销/驳回后回退为未点名 |
| 通知 | 提交、通过、驳回三个触点，学员与家长都收 |

### 5.3 费用闭环（账单 vs 流水）

```
账单 bills（应收）──▶ 待缴 ──部分缴──▶ 部分缴 ──缴清──▶ 已缴
   │                    │
   │                    └── 到期未清 ──▶ 已逾期（查询时计算）
   └── 作废 ──▶ 已作废

流水 payments（实收）──▶ 待确认 ──确认──▶ 已支付 ──退款──▶ 已退款
                              └── 作废 ──▶ 已作废
```

| 口径 | 定义 |
| --- | --- |
| 应缴 | Σ 有效账单金额（不含已作废） |
| 已缴 | Σ 已支付流水金额（不含待确认 / 已退款 / 已作废） |
| 欠费 | max(应缴 − 已缴, 0) |
| 对账 | 家长端每一笔都能在后台缴费管理找到同号流水；汇总差额 = 0 |

> 兼容策略：`payments` 增加可空 `billId` 列；历史数据不回填，家长端归入「历史流水」；新建账单时由财务或「按课程价批量生成」脚本创建。

### 5.4 课表生成（规则 → 课次）

```
班级排课规则（周几 + 起止时间 + 生效区间 + 教室）
   │ 生成（幂等：唯一键 classId + sessionDate + startTime）
   ▼
课次 class_sessions（待上课）
   │ 例外：调课（改时间 + 原课次标记）/ 停课（已取消）/ 节假日跳过
   ▼
三端课表读取同一份课次数据
```

- 生成算法：从 `effectiveFrom` 到 `min(effectiveTo, class.endDate)` 逐日匹配 `weekday`；跳过 `holidays` 配置日期；单班课次量级 = 周次数 × 周数（约 16–40 条）。
- 修改规则只影响**未来未上课**的课次：已上课的课次不改；未上课的旧课次标记「已取消（重新排课）」并重新生成。
- 迁移：旧 `classes.schedule` 文本保留为展示字段；上线时提供「排课向导」把「周六 09:00-10:30」解析为规则，解析失败的班级由教务手工补录。

### 6.3 状态机汇总

| 实体 | 状态流转 |
| --- | --- |
| 课次 `class_sessions` | 待上课 → 已上课 → 已结课；待上课 → 已取消；待上课 → 已调课（原课次） |
| 作业 `homeworks` | 草稿 → 已发布 → 已截止 → 已归档 |
| 提交 `homework_submissions` | 未提交 → 已提交 → 已批改；已提交 → 退回重做 → 已提交 |
| 请假 `leave_requests` | 待审批 → 已通过 → 已销假；待审批 → 已驳回；待审批 → 已撤销 |
| 考勤 `attendance` | 未点名 → 出勤 / 迟到 / 早退 / 请假 / 缺勤 |
| 账单 `bills` | 待缴 → 部分缴 → 已缴；待缴 / 部分缴 → 已逾期（派生）；任意 → 已作废 |

### 6.4 删除与留痕

| 场景 | 规则 |
| --- | --- |
| 删课次 | 有考勤 / 作业 / 请假 → 拒绝（409），只能「取消」 |
| 删作业 | 有提交 → 拒绝，只能「归档」 |
| 删请假 | 不存在物理删除；仅撤销（待审批）或保留记录 |
| 删账单 | 有已支付流水 → 拒绝；否则作废而非删除 |
| 删学员 | 沿用现有级联规则；考勤 / 作业 / 请假 / 账单按「有则拒绝、无则软删」保护，避免误删教学轨迹 |
| 审批 / 批改 / 考勤修改 | 记录操作人与时间；修改考勤需备注（P1 留原值） |

### 6.5 量级与索引

- 课次：约 20 班 × 20 周 × 2 次/周 ≈ 800 条/学期，全表可缓存；
- 作业：每班每周 1–2 次 → 千级/学期；提交：学员数 × 作业数 → 万级/学期；
- 考勤：课次 × 学员 → 2–3 万/学期，**必须走 `uk(sessionId, studentId)`**；
- 通知：按账号分页，90 天归档；
- 附件：单文件 ≤ 20MB，建议 `uploads/{yyyyMM}/{uuid}` 分目录，磁盘配额告警。

## 7. 接口设计

### 7.1 约定

- 沿用 `/api/v1`、统一响应壳 `{code, message, data}`、分页 `page / pageSize`；
- **每个接口在服务层解析「数据范围」**：教师 → `classIds = 本人授课班`；家长 → `studentIds = student_parents 关联`；学员 → 自己的 `studentId`；
- 门禁：`require_teacher / require_student / require_parent`；后台接口继续 `require_roles`；
- 写操作返回受影响实体，便于前端局部刷新（不整页 `hydrate()`）。

## 9. 非功能需求

### 9.1 移动端与可用性

- 390px 宽度下无横向滚动；触控目标 ≥ 44px；表单键盘弹起不遮挡提交按钮；
- 图片 / 附件展示限制高度，长文本折叠；
- 弱网：列表骨架屏、提交防重复点击、失败可重试且不产生重复数据（幂等键）。

### 9.2 附件安全

- 类型白名单 + 大小上限（单文件 20MB，单次 3 个）；
- 存储目录不在静态根下，下载走 `/files/{id}` 鉴权（校验归属：提交人 / 教师 / 家长）；
- 文件名不落原始路径（UUID 存储），展示原名；后续接 OSS + 哈希秒传（《01》§11.7）。

### 9.3 通知

| 阶段 | 渠道 | 触达点 |
| --- | --- | --- |
| P0 | 站内信（登录可见 + 未读角标） | 作业发布 / 批改 / 退回、请假结果、缴费提醒、公告 |
| P1 | 微信服务号模板消息 | 上课提醒、缺勤告警、作业截止前 24h |
| P2 | 短信 | 仅缺勤等强触达场景（成本敏感，需开关） |

### 9.4 审计与隐私

- 审批、批改、考勤修改、账单作废必须留痕（操作人 / 时间 / 前后值）；
- 家长端只展示自己孩子的数据；列表接口手机号脱敏（`158****0001`）；
- 日志不记录作业正文、请假事由等敏感内容。

### 9.5 性能

- 课表一次查询 ≤ 100ms（单班一学期 < 100 条）；
- 作业 / 考勤列表分页 20 条；
- 点名批量提交单事务，20 人 < 50ms。

## 10. 优先级与排期

### 10.1 分期

| 期 | 范围 | 交付价值 | 预估 |
| --- | --- | --- | --- |
| **P0** | 排课规则 + 课次 + 三端课表；作业（布置 / 提交 / 批改）；请假（申请 / 审批 / 考勤联动）；家长缴费详情（过渡口径）；站内通知；多孩切换 | 三端从「能看」到「能办」，用户点名的 7 件事全部覆盖 | 18–22 人日 |
| **P1** | 账单 `bills` + 对账；考勤统计 / 出勤率；作业统计 / 催交；缺勤告警 / 上课提醒；调课 / 补课；课件范围与教师上传；阶段报告 / 评语 | 运营闭环 + 家长端信任度 | 18–22 人日 |
| **P2** | 在线支付；微信模板消息；发票 / 退费；课程评价；报告导出 PDF；家长留言 | 增收与体验升级 | 20–25 人日 |

### 10.2 P0 拆解（建议 3 个迭代）

| 迭代 | 内容 | 人日 |
| --- | --- | --- |
| S1 | 数据模型 + 迁移；排课规则 / 课次生成；三端课表接口与页面（先只读） | 6 |
| S2 | 作业全链路（教师布置 / 批改、学员提交）；附件上传与鉴权下载；通知基础 | 8 |
| S3 | 请假全链路 + 考勤联动；家长缴费详情（过渡）；多孩切换；联调与越权测试 | 8 |

> 依赖顺序不可颠倒：**课次 → 作业 / 请假 / 考勤**。作业与请假可并行开发（都依赖课次），缴费详情与课次无关，可提前并行。

### 10.3 建议不做（控制范围）

在线直播 / 录播、IM 即时聊天、题库与自动判题、复杂 RBAC 自定义角色、多校区 / 多租户、家长端在线支付（P2 前一律线下登记 + 后台确认）。这些都会把 4 周的最小闭环拖成 3 个月。

## 11. 验收标准（关键断言）

| # | 场景 | 期望 |
| --- | --- | --- |
| 1 | 学员 XS001 打开课表 | 仅显示 BJ002 课次，时间 / 教室 / 教师与后台一致 |
| 2 | 学员 XS002 请求 XS001 的作业详情 | 403，且不泄露标题 |
| 3 | 学员在截止前提交作业两次 | 只保留最后一次，版本号 +1，教师端显示最新 |
| 4 | 截止后提交且 `allowLate=false` | 409「已截止，不允许迟交」 |
| 5 | 教师批改后学员再提交 | 拒绝（409「已批改」），需先退回 |

| 7 | 教师通过请假 | 考勤自动为「请假」，学员 / 家长课表打「已请假」，双方收到通知 |

| 9 | 教师 A 审批教师 B 班级请假 | 403 |

| 11 | 家长查看缴费汇总 | 应缴 / 已缴 / 欠费与后台逐笔核对差额为 0；待确认不计入已缴 |
| 12 | 财务作废一笔流水 | 家长端已缴与欠费实时回滚 |
| 13 | 家长切换非关联孩子 | 403 |
| 14 | 删除有提交的作业 | 409，提示「已有学员提交」 |
| 15 | 调课后学员课表 | 显示「原时间 → 新时间」，原时间置灰可追溯 |
| 16 | 附件下载越权 | 非归属人访问 403，不能通过猜 URL 拿到文件 |
| 17 | 重复点名 / 重复审批 | 幂等，不产生重复记录 |
| 18 | 旧数据兼容 | 无 `billId` 的历史流水显示「历史流水」，不产生虚假欠费 |

## 12. 待确认问题（需业务拍板）

| # | 问题 | 影响 | 建议默认值 |
| --- | --- | --- | --- |
| 1 | 作业是否需要附件上传与打分，还是只做「提交 / 已交」？ | 工作量 ±3 人日；影响表结构 | 要附件与打分（家长最看重分数 / 评语） |
| 2 | 作业是否允许迟交、退回重做？ | 状态机复杂度 | 允许迟交（作业级开关）+ 退回重做 |
| 3 | 请假是「按课次」还是「按日期区间」？审批几级？ | 表结构与考勤联动 | 按课次多选；一级审批（任课教师），教务可代批 |
| 4 | 家长是否需要在线支付？ | 直接决定是否接微信 / 支付宝、是否做对账与回调 | P2 之前不做，线下收款 + 后台确认 |
| 5 | 是否需要课时消耗 / 剩余课时（按课次扣课时）？ | 是否引入 `enrollments`（《01》§11.1）与课包 | P1 做「已上 / 总课时」估算，暂不扣课包 |
| 6 | 是否需要微信通知？ | 触达率与开发量（公众号 / 模板消息资质） | P1 接服务号模板消息 |
| 7 | 教师「授课查看」是否要包含教案 / 教学计划？ | 页面复杂度 | P0 不含；P2 可作为课件扩展 |
| 8 | 家长能否代交作业？ | 作业真实性 | 不允许；仅允许代请假 |
| 9 | 请假通过后能否销假（提前返校）？ | 考勤修正流程 | 不做销假，由教师修改考勤（带备注） |
| 10 | 是否需要多校区 / 多机构？ | 所有表是否加 `tenantId` | 不做，维持单机构假设（《02》§2.3） |
| 11 | 附件存本地还是对象存储？ | 部署与备份 | P0 本地磁盘 + 鉴权下载；P1 可切 OSS |
| 12 | 历史缴费数据是否补建账单？ | 家长端欠费口径 | 不补建，标记「历史流水」；新学员起用账单 |
